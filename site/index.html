MCP server

Every built-in YouTrack tool, and the ones it lacks

ymcp ships every tool of YouTrack’s own MCP server under the same names, arguments and limits, then adds deleting, sprints, attachments, history, time reports and commands. It works with self-hosted instances behind a VPN.

Why it is easy to run

  • Signs in like the web UI. No admin-issued token or OAuth client. The password lives in your system keychain.
  • Works without admin rights. Field schemas, groups and comments fall back to what a regular user can read.
  • One-command install. ymcp setup registers itself in Claude, Cursor, VS Code, Zed, Codex, Gemini and more.
  • A single static binary for macOS, Linux and Windows, with ymcp update built in.

Why models get it right

  • Fields by display name. {"State": "In Progress"} is checked against the project before it is sent.
  • Errors say what to do next: the allowed values, which tool finds the right ID after a 404, that a 403 needs a permission.
  • Destructive tools are marked with destructiveHint, so clients ask before deleting.
  • Prompts clients offer as slash commands.

Tools marked + are ymcp’s extras; the rest are YouTrack’s own. Red ones delete or bulk-change data, so clients ask first.

Serve only what you need: ymcp serve --tools issues,comments,-delete_issue

Pipelines

A YouTrack search in, pull requests out

A pipeline watches a search and gives each issue it finds to a coding agent, in its own git worktree on a new branch. ymcp pushes the branch, opens the pull or merge request and brings the agent the review comments until the change is merged.

Backlog

The source query found the issue and no run has taken it yet.

Working

The agent works on it in its worktree.

State In Progress

Needs input

The agent asked a question or wants a permission. You get a notification.

tag needs-input

Review

The branch is pushed and the agent answers review comments.

State Fixed

Done or closed

The change is merged, or closed without one. The run ends either way.

Agents

Each run gets its own MCP server with the same YouTrack tools. Your password never reaches the agent.

    Strategies

    Where the work goes once the agent is done.

      A TUI, or scripts

      A board per pipeline and an inbox of runs that wait for you. Or plain commands:

      • ymcp pipeline new
      • ymcp pipeline NAME check
      • ymcp pipeline NAME run -d

      Clients

      Set up in the clients you already use

      ymcp setup adds each YouTrack instance as its own server in the clients you pick, and removes it from the ones you uncheck.

      Or run it once for the whole team: ymcp serve --transport http serves every profile on one port, behind a token.

      Sign-in

      The same way the YouTrack web app does

      YouTrack’s OAuth password grant needs a service secret that regular users don’t have, so ymcp goes through the web login instead.

      1. Read the Hub location and YouTrack service ID from the public /api/config.
      2. Submit the Hub login form and keep the session cookie.
      3. Run the web client’s implicit OAuth flow and take the bearer token from the redirect.

      Expired tokens are renewed from the session, without resending the password.
